# SEO・アクセス解析 初期設定ガイド

> ポートフォリオ、LP、企業サイトで使える初期設定手順。  
> 数か月後に見返しても、そのまま作業を再開できるように、設定順と確認方法をまとめています。

---

## 0. このガイドの使い方

### 対象

- ポートフォリオサイト
- LP
- WordPressサイト
- 企業サイト
- 保守管理を引き継いだサイト

### 基本の流れ

```text
Googleアカウント準備
↓
Search Console登録
↓
GA4作成
↓
Google Tag Manager設置
↓
計測確認
↓
Search ConsoleとGA4を連携
↓
サイトマップ送信
↓
インデックス確認
↓
SEO・コンテンツ改善
```

- パスワードそのものはNotionなどへ直接書かず、Bitwardenで管理する

# フェーズ2：Google Search Consoleを設定する

## 1. プロパティを追加する

Search Consoleで対象サイトを登録する。

### URLプレフィックス

```text
https://www.example.com/
```

次のような場合に向いている。

- WordPressサイト
- HTMLタグで所有権確認したい
- DNSを変更せずに設定したい

### ドメインプロパティ

```text
example.com
```

次のような場合に向いている。

- DNSを管理できる
- `www`あり・なし、`http`・`https`をまとめて管理したい

## チェックリスト

- [ ] URLが本番サイトと完全に一致している
- [ ] `https://`になっている
- [ ] `www`あり・なしを確認した
- [ ] 適切なプロパティ形式を選択した

---

## 2. 所有権を確認する

### WordPressでHTMLタグを使う場合

おすすめの流れ：

```text
Search ConsoleでHTMLタグを取得
↓
WordPressにWPCodeをインストール
↓
「Header & Footer」を開く
↓
Header欄へHTMLタグを貼り付け
↓
保存
↓
Search Consoleで「確認」
```

### 注意

- テーマの `header.php` は直接編集しない
- テーマ更新で消える可能性があるため、WPCodeなどを使う
- キャッシュプラグインがある場合は、保存後にキャッシュを削除する

## 完了状態

```text
所有権を証明しました
```

## チェックリスト

- [ ] 所有権確認タグを設置
- [ ] Search Consoleで確認成功
- [ ] 管理台帳にプロパティURLを記録
- [ ] 必要に応じて他の担当者へ権限付与

# フェーズ3：Google Analytics 4を作成する

## 1. GA4プロパティを作成する

設定例：

- プロパティ名：サイト名または企業名
- レポートのタイムゾーン：日本
- 通貨：日本円
- 業種：事業内容に最も近いもの
- ビジネス規模：企業そのものの従業員数を基準に選択
- ビジネス目標：問い合わせ獲得なら「見込み顧客の発掘」

## 2. Webデータストリームを作成する

```text

```

登録するもの：

- サイトURL
- ストリーム名
- 拡張計測機能

通常、拡張計測機能はオンのままでよい。

## 3. 測定IDを記録する

```text
G-XXXXXXXXXX
```

- キャッシュが残っていないか

# フェーズ7：サイトマップを確認・送信する

## 1. サイトマップURLを確認する

代表的なURL：

```text
https://www.example.com/sitemap.xml
```

```text
https://www.example.com/sitemap_index.xml
```

```text
https://www.example.com/sitemap-index.xml
```

```text
https://www.example.com/wp-sitemap.xml
```

### WordPressの場合

- WordPress標準：`wp-sitemap.xml`
- SEOプラグイン：`sitemap_index.xml`など
- 制作会社独自：`sitemap.xml`の場合もある

まずブラウザで開き、XMLが表示されるか確認する。

## 2. Search Consoleへ送信する

Search Consoleの「サイトマップ」を開く。

プロパティURLが次の場合：

```text
https://www.example.com/
```

入力欄には通常、次の部分だけ入力する。

```text
sitemap.xml
```

## 完了状態

```text
成功しました
```

## 送信直後の表示について

送信直後に次の表示になることがある。

```text
型不明
ステータスを取得できませんでした
```

サイトマップURLをブラウザで正常に開ける場合は、Google側の処理待ちの可能性がある。

### 対応

1. サイトマップがブラウザで表示されるか確認
2. プロパティURLとサイトマップURLが一致しているか確認
3. 数分〜24時間ほど待つ
4. 再度Search Consoleを確認

24〜48時間経っても成功しない場合は、URLやXML形式、サーバー応答を確認する。

## チェックリスト

- [ ] サイトマップURLを確認
- [ ] ブラウザで正常表示
- [ ] Search Consoleへ送信
- [ ] ステータスが「成功しました」になった

# フェーズ8：robots.txtを確認する

## 確認URL

```text
https://www.example.com/robots.txt
```

## 基本例

```text

```

## WordPressの場合

WordPressが仮想的に生成している場合があるため、必ずしもファイルを手動作成する必要はない。

### 確認ポイント

- サイト全体を誤ってブロックしていないか
- サイトマップURLが正しいか
- 本番環境で `Disallow: /` になっていないか

## チェックリスト

- [ ] robots.txtが表示される
- [ ] サイト全体がブロックされていない

# フェーズ9：インデックス状況を確認する

## URL検査

Search Console上部の検索欄へ、確認したいURLを入力する。

### 優先して確認するページ

1. トップページ
2. 主要サービスページ
3. お問い合わせページ
4. 新しく公開した重要ページ

## インデックス未登録の場合

必要に応じて次を実行する。

```text
インデックス登録をリクエスト
```

### 注意

- すべてのページを手動でリクエストする必要はない
- サイトマップと内部リンクが正常なら、Googleは順次クロールする
- リクエストしても必ず登録されるとは限らない

## チェックリスト

- [ ] 主要ページをURL検査

# フェーズ10：検索結果向けの基本SEO設定

## 1. Titleタグ

```html
<title>ページタイトル｜サイト名</title>
```

### 確認ポイント

- ページごとに固有のタイトル
- 内容が分かる
- 重要なキーワードを自然に含める
- 不自然なキーワードの詰め込みをしない

---

## 2. Meta Description

```html
<meta
  name="description"
  content="ページの内容を簡潔に説明する文章を設定します。"
>
```

### 確認ポイント

- ページごとに内容を変える
- 検索結果でクリックしたくなる説明にする
- ページ内容と一致させる

---

## 3. Canonical

```html
<link rel="canonical" href="https://www.example.com/">
```

### 用途

- 正規URLをGoogleへ伝える
- URLの重複評価を防ぐ

---

## 4. Robots Meta

```html
<meta name="robots" content="index, follow">
```

本番公開時に `noindex` が残っていないか確認する。

---

## 5. OGP

```html
<meta property="og:title" content="サイトタイトル">
<meta property="og:description" content="サイトの説明">
<meta property="og:image" content="https://www.example.com/ogp.jpg">
<meta property="og:url" content="https://www.example.com/">
<meta property="og:type" content="website">
```

### 確認ポイント

- OGP画像が絶対URLになっている
- SNSで共有したときのタイトル・説明が適切
- 下層ページは必要に応じて `article` を使用

## チェックリスト

- [ ] Title設定
- [ ] Description設定
- [ ] Canonical設定
- [ ] Robots Meta確認
- [ ] OGP設定
- [ ] 本番環境にnoindexが残っていない

# フェーズ11：コンテンツと構造を確認する

## 1. 見出し構造

```html
<h1>ページタイトル</h1>
<h2>大きなセクション</h2>
<h3>セクション内の詳細</h3>
```

### 確認ポイント

- h1はページの主題を表す
- h2、h3の階層が自然
- デザイン目的だけで見出しタグを選ばない

---

## 2. 画像のalt属性

```html
<img src="example.jpg" alt="画像の内容が分かる説明">
```

### altを書かなくてよい例

装飾だけの画像：

```html
<img src="decoration.svg" alt="">
```

---

## 3. 内部リンク

### 確認ポイント

- グローバルナビゲーションがある
- トップページから主要ページへ移動できる
- フッターに必要なリンクがある
- 関連ページ同士がつながっている
- 孤立ページがない

---

## 4. 制作実績ページ

最低限、次を掲載する。

- 制作概要
- 制作意図
- 担当範囲
- 使用技術
- 課題
- 解決方法
- 工夫した点
- 成果

---

## 5. 記事・コラム

サイトの目的に応じて、役立つコンテンツを追加する。

例：

- よくある質問
- 制作ノウハウ
- サービスの選び方
- 事例紹介
- お客様の悩みを解決する記事

# フェーズ12：問い合わせ計測を設定する

- 送信ボタンクリックだけでは、送信失敗も計測される場合がある
- 可能なら完了ページ表示または送信成功イベントを使う
- 個人情報をGA4へ送信しない

# よくあるトラブル

## Search Consoleで所有権確認できない

確認すること：

- HTMLタグがHeader内に入っているか
- タグを省略せずそのまま貼ったか
- WPCodeを保存したか
- キャッシュを削除したか
- 正しいSearch Consoleプロパティを確認しているか

---

## GA4リアルタイムに表示されない

確認すること：

- GTMを公開したか
- 測定IDが正しいか
- タグのトリガーが全ページか
- GTMコードが正しく設置されているか
- 広告ブロッカーを使用していないか

---

## サイトマップが「型不明」になる

確認すること：

- ブラウザでサイトマップが表示できるか
- Search ConsoleのプロパティとURLが一致しているか
- サイトマップのURLを間違えていないか
- 送信後、しばらく時間を置いたか

正常に表示できている場合、Google側の処理待ちで後から「成功しました」に変わることがある。

---

## インデックスされない

確認すること：

- `noindex` が付いていないか
- robots.txtでブロックされていないか
- canonicalが別URLを向いていないか
- ページが内部リンクから到達できるか
- 内容が極端に少なくないか
- サーバーエラーが出ていないか

---

# 補足

## Keywordsタグ

```html
<meta name="keywords" content="...">
```

Google検索の評価目的では基本的に不要。

---

## インデックス反映までの時間

数時間で反映されることもあれば、数日〜数週間かかることもある。

```text
インデックス登録をリクエストした
＝必ずすぐ検索結果に表示される
```

ではない。

---

## SEOの考え方

```text
初期設定
↓
Googleがサイトを発見・理解できる状態を作る
↓
アクセスと検索データを計測する
↓
ユーザーの悩みに合うコンテンツを増やす
↓
データを見ながら改善する
```

初期設定は「検索順位を上げる作業」そのものではなく、検索されるための土台作り。
